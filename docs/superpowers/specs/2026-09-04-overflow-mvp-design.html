Design spec · 04 September 2026

Turn spare capacity into mutual credit.

Overflow coordinates GitHub work between peers. Merged pull requests create zero-sum credit; ratings follow difficulty, review friction lowers the award, self-work never enters the ledger, and miscalibration escalates through an auditable ladder.

01

Product contract

A reciprocal work exchange, not a marketplace and not a token meter.

The invariant

Every posted award is one balanced transaction: the contributor receives +N, the repository sponsor receives −N. The sum of all accounts remains zero.

Self-work

Recorded as evidence, worth zero, and emits no ledger entries—even if repository ownership changes later.

Member

Signs in with GitHub, browses eligible work, contributes, and can open an audit.

Sponsor

The one accountable member who explicitly registers a repository and receives its debits.

Moderator

Resolves calibration evidence and advances warnings, recalibration, or bans.

02

GitHub flow

Only specifically registered repositories participate.

1 · SIGN INAuth.js GitHub OAuth persists the member identity and an AES-256-GCM encrypted access token.
2 · REGISTERThe member submits owner/name or a GitHub URL. Overflow verifies admin permission, creates the webhook and ten overflow:1..10 labels, then imports that repository's eligible issues—nothing else.
3 · CONTRIBUTEA registered member opens a PR that closes exactly one eligible issue. GitHub remains the collaboration interface.
4 · MERGEA signed webhook triggers idempotent evaluation. Unregistered authors become unclaimed records; banned accounts and inactive repositories cannot post credit.
03

Difficulty, not churn

The issue label is the proposal; a PR label can recalibrate it after the diff is understood.

rated difficulty = PR overflow label, otherwise issue overflow label
review rounds     = unique CHANGES_REQUESTED review IDs before merge
awarded credits   = max(0, rated difficulty - review rounds)

Included evidence

  • Issue intent and constraints
  • PR diff and resulting behavior
  • Difficulty labels
  • Changes-requested reviews

Never scored

  • Lines added or deleted
  • File or commit count
  • Elapsed time
  • Generated churn

Ambiguity

Multiple difficulty labels or multiple eligible closing issues create NEEDS_AUDIT; the service never guesses.

Evidence retention

Store GitHub URLs, text metadata, labels, merge SHA and a SHA-256 fingerprint of the fetched diff. Fetch source patches on demand; do not duplicate repository code in the database.

07

Security and failures

Authenticate at the edge, authorize at each mutation, and preserve failed delivery evidence.

Webhook

Verify raw-body HMAC with constant-time comparison before JSON parsing. Deduplicate on X-GitHub-Delivery.

Tokens

Encrypt with AES-256-GCM and a base64 32-byte environment key. Never log plaintext.

Database

Parameterized SQL plus transactions for state transitions, contributions and balanced entries.

Registration rollback

When GitHub setup fails, do not leave a local active repository. When a later local write fails after webhook creation, attempt external webhook cleanup and surface the recoverable error.

08

Behavior is test-first; integration is independently reviewed.
