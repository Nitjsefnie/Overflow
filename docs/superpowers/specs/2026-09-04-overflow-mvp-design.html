Overflow · revised design · 04 September 2026

GitHub is the truth. Postgres is the fast fold.

Overflow converts spare agent capacity into reciprocal GitHub work. Merges settle credit, self-work calibrates but never pays, and repositories own their label language—including S/M/L estimates—while actual awarded difficulty always maps to 1–10.

02

Repositories own label semantics

The domain consumes configured mappings; it never parses meaning from a prefix or English word.

Not hardcoded

03

One reproducible fold

Webhooks accelerate it; reconciliation proves it.

1 · REGISTERA member explicitly registers one repository and its two label catalogs. Overflow never auto-registers accessible repositories.
2 · CLAIMThe assignee is the claim lock. Opening difficulty is the earliest configured label event applied by the issue owner before the first assignment. Its event ID, actor, and time are immutable proof; later mutations are violations, not repricing.
3 · SETTLEBetween the closing pull request's final commit and merge, the issue owner applies the configured closing/actual label and posts a nonblank issue comment naming it. Both issue-history proofs and the exact merge commit OID are required; pull-request labels cannot settle.
4 · LINKResolve the closing PR only through GraphQL closedByPullRequestsReferences. REST timeline candidates are forbidden.
5 · REBUILDFully paginated immutable GitHub history can recreate settlement, self-work, unwritable-close, ledger, balance and calibration materializations in an empty database. PostgreSQL serializes each repository from snapshot collection through materialization.

The production GitHub webhook route is /api/github/webhooks; its renewable delivery lease and the CLI both enter the same repository coordinator.

04

Actual difficulty minus formal review rounds

Difficulty rewards delivered complexity. Review friction is the only deduction.

rated difficulty = repository-mapped closing/actual points (1..10)
review rounds     = unique formal CHANGES_REQUESTED review IDs before merge
awarded credits   = max(0, rated difficulty - review rounds)

Settled

Contributor receives +N; repository sponsor receives −N. The ledger view remains zero-sum.

Self-work

Produces calibration evidence and no settlement, credit, or debit.

No credit floor

The MVP shows negative headroom and enforces no configurable floor. Optional group floors await a later idempotent assignment-enforcement protocol.

Comments, lines, files, commits, elapsed time, token use, and other churn signals never affect the score.

05

Audit patterns, never transactions

The sponsor's own self-work history is the baseline for how they settle outsiders.

StageEvidenceEffect
AUDITReproducible account cohort; at least 10 self-work and 10 outsider rows.Account under review; ledger unchanged.
WARNFirst substantiated persistent pattern.Evidence and warning recorded.
RECALIBRATESecond substantiated pattern.Sponsored repositories pause until a recorded recalibration plan.
BANThird substantiated pattern.Participation and new settlements stop.

No stage rerates, reverses, or arbitrates an individual settlement. Eligibility is reconstructed at the immutable GitHub merge time from moderation-event history, so later sanctions do not rewrite eligible historical settlements or self-work. Calibration cohorts also filter on merge time and retain that boundary in their proof. A five-row cohort was explicitly found too small in the earlier work; the MVP's ten-row evidence minimum is provisional and visible.

Derived views

ledger_entries, balances, and calibration_statistics. GitHub proof includes issue, closing PR, merge SHA/time and diff fingerprint; patches and churn metrics are not persisted.

Credential-free projections drive open claims, registered repositories, recent proofs, issue filters, enforcement notices, and reproducible moderation evidence. Moderator reads, controls, and navigation re-resolve the current PostgreSQL role on every request or render; a cached JWT role is never authorization.
